# SMS 项目进度与企业级 AI 应用对齐评估

> 更新日期：2026-09-15
> 评估范围：Maven 多模块后端、`sms-ui`、初始化 SQL，以及当前 AI、知识库与任务编排代码。
> 技术基线：Java 21、Spring Boot 3.5、Dubbo 3.3、Nacos、MyBatis-Plus、Redis、LangChain4j、MySQL、PostgreSQL/pgvector、Vue 3。

## 1. 目标与结论

项目目标是建设可审计、可恢复、可扩展的企业级 AI 应用平台，而不是仅提供一次性聊天接口。核心闭环应为：

```text
认证与租户上下文
  -> 会话请求 / 幂等 Run
  -> PLAN（结构化校验）
  -> TOOL / RAG（权限、超时、重试）
  -> COMPOSE（流式回答与引用）
  -> 审计、指标、评测与运营
```

当前项目已经完成了从模型接入、任务规划、工具执行、RAG 数据模型到 run/step 生命周期的一部分骨架，并已经有学生查询和知识检索两个工具方向。项目处于“可继续联调的工程原型”阶段，尚未达到测试环境可安全推广，更不具备生产上线条件。

最优先的阻塞不是继续新增工具，而是修复向量导入、收紧安全边界、完成真实认证与测试/观测闭环。

## 2. 当前模块与边界

| 模块 | 当前职责 | 评估 |
|---|---|---|
| `sms-common-core` | 通用响应、基础 DTO 与枚举 | 基础能力可用，需继续统一错误码与追踪上下文。 |
| `sms-common-persistent` | MyBatis-Plus 基类、模型/提示词/工具定义、task run/step 实体 | 已开始承载共享持久化模型，方向正确。 |
| `sms-ai` | 会话编排、模型接入、规划、工具执行、SSE、知识导入 | 核心 AI 模块，但内部仍处于从平铺包结构向分层演进阶段。 |
| `sms-student` | 学生领域 Dubbo API 与 Provider | 已作为首个结构化查询工具领域。 |
| `sms-knowledge` | 知识库元数据、向量检索、Milvus/pgvector 适配 | 已有检索骨架，索引生产链路尚未可用。 |
| `sms-web` | Web 服务壳 | AI 业务边界尚未明确。 |
| `sms-ui` | Vue 管理端与聊天界面 | 具备 UI 基础，需完成真实 SSE、run 状态与知识库运营页面。 |

## 3. 已完成能力

### 3.1 模型与聊天基础能力

- 已实现数据库驱动的模型定义、模型别名、回退别名和 OpenAI 兼容模型适配。
- 已接入 LangChain4j 聊天与流式聊天能力，聊天记忆通过 Redis `ChatMemoryStore` 保存。
- 已具备请求日志、工具执行日志与 SSE `start/planning/executing/generating/token/done/error` 事件基础。
- 模型密钥已支持从本地环境变量读取；生产环境仍需接入密钥管理系统。

### 3.2 规划、工具与会话编排

- `TaskPlannerService` 已将用户问题转换为结构化 `AiTask` 列表，并校验 domain、toolName 与已注册工具的一致性。
- 已提供数据库工具定义、`AiToolRegistry` 和领域执行器；学生查询和知识检索已经接入执行器路径。
- 已完成 `ConversationApplicationService` 的 `PLAN -> TOOL -> COMPOSE` 编排，`AiPlanService` 已收敛为兼容门面。
- 已建立 `ai_task_run` 与 `ai_task_step` DDL 和实体，记录规划、工具和生成步骤的输入、输出、状态、尝试次数、超时、租约、错误和幂等键。
- `/api/ai/chat` 首个 SSE 事件返回 `runId`，请求支持 `idempotencyKey`；已提供 `POST /api/ai/runs/{runId}/cancel`。
- 工具步骤有超时、指数退避重试和租约过期回收；应用重启后调度器能重新领取超时或到期重试的 TOOL 步骤。

### 3.3 知识库与向量数据模型

- 已有知识库、文档、版本、内容明细、入库任务的 MySQL 表结构。
- 已提供 LangChain4j 中文测试文档、文档版本和 12 个内容分块。
- 已提供 PostgreSQL/pgvector `ai_knowledge_chunk` 表结构，向量维度统一为 1356，并包含文档版本和分块幂等唯一键。
- 已有 OpenAI 兼容 embedding 客户端、MySQL 明细读取、PostgreSQL upsert 导入接口，以及检索侧的 pgvector 适配。

### 3.4 工程基础

- Maven 多模块可编译，`sms-ai` 及其直接依赖已通过 `mvn -pl sms-ai -am -DskipTests compile`。
- 后端具备 Nacos/Dubbo 基础集成，前端具备 Vue 3、TypeScript、Pinia、Element Plus 工具链。

## 4. 未完成与当前阻塞

### P0：向量导入当前不可用

1. 当前 OpenAI 兼容代理的 `/v1/models` 未返回任何 embedding 模型；调用 `text-embedding-3-small` 返回 `model_not_found`。因此内容无法生成向量，不能写入 pgvector。
2. `KnowledgeDocumentIngestionService` 当前存在临时硬编码：`limit=10`、`indexRevision=1`，并固定调用 `loadDetails(1L, 1L, limit)`，导致 API 请求中的知识库、文档版本和 limit 参数未生效。
3. 向量维度依赖模型服务支持 `dimensions=1356`。切换供应商前必须验证模型可用性、返回长度和 pgvector 表结构一致性。

完成定义：使用可用 embedding 模型导入指定知识库/文档版本；重复导入不产生重复 chunk；可通过检索 API 找回正确来源、分块编号和相似度。

### P0：认证、授权与数据保护未达到企业要求

- `TempAuthController` 是内存演示认证，不具备密码哈希、会话持久化、刷新、撤销、审计或多租户隔离能力。
- AI 请求仍可由客户端传入用户和会话标识；正式实现必须从认证上下文获取 userId、tenantId、角色和数据范围。
- 调试接口及工具返回结果需要统一字段白名单、数据脱敏和行级权限控制；模型不能直接获取邮箱、手机号等敏感字段。
- 用户问题、业务上下文和工具结果直接进入提示词，尚未形成提示词注入防护、敏感数据分类和留存策略。

### P0：任务恢复仅覆盖工具步骤

- 当前恢复调度器可重试已持久化的 TOOL 步骤，但无法从任意中断点完整恢复 PLAN、COMPOSE、SSE 订阅和最终回答。
- 流式模型生成取消是协作式的：run 状态会被标记取消，但不能保证上游模型连接已被主动终止。
- run/step 状态更新、外部工具调用和 SSE 回调之间缺少 Outbox/事件日志，进程崩溃边界仍可能造成重复执行或状态不一致。

### P1：结构化输出与工具治理不足

- 规划 JSON 已做格式、domain 和工具存在性检查，但尚未使用 JSON Schema/Bean Validation 校验字段类型、必填项、嵌套 query、最大任务数和语义约束。
- 工具定义缺少版本审批、灰度、缓存刷新、执行器契约校验和管理 API。
- 工具调用需增加租户、角色、字段、数据行、最大返回量、超时和成本策略；禁止模型驱动任意 SQL、任意 Bean 或任意 HTTP 地址。

### P1：RAG 工程链路不完整

- 尚无文件上传、格式解析、文本抽取、切分策略版本、异步索引队列、失败重放和索引状态运营页。
- MySQL 暂存明细、PostgreSQL 向量表和知识服务的版本/状态契约仍需用迁移脚本统一，避免 DDL 漂移。
- 知识检索尚未完成按租户、知识库、文档、有效版本和 ACL 的过滤；回答侧需要显式引用来源并支持不可回答策略。

### P1：前端与 API 闭环不完整

- 聊天 UI 需要接入真实 SSE，处理 `runId`、token 流、重连、停止生成、失败重试和历史恢复。
- 需要知识库、文档、分块、索引任务和失败原因的管理页面。
- 需要 run/step 查询页面，供运营人员追踪规划、工具输入输出、重试和取消。

### P1：可观测性、测试和运维不足

- 当前以请求/工具日志为主，未形成 traceId 贯穿、Prometheus/Micrometer 指标、模型成本统计、告警和仪表盘。
- 现有测试主要是 Spring 上下文和临时认证测试；缺少 planner、状态机、重试、取消、恢复、向量导入、权限和 SSE 合约测试。
- 尚未建立 CI 质量门禁、数据库迁移版本管理、容器化部署、健康检查、容量规划和备份恢复演练。

## 5. 待优化项

| 主题 | 现状问题 | 优化方向 |
|---|---|---|
| 包结构 | `model`、`service`、`mapper` 中混放领域、应用和基础设施职责 | 演进为 `api`、`application`、`domain`、`infrastructure`，按会话、工具、知识库划分子域。 |
| 异步执行 | 本地线程池负责工作流，扩缩容和跨实例恢复能力有限 | 任务状态持久化后接入消息队列或调度 worker；使用分布式租约和幂等消费。 |
| 状态机 | 状态以字符串表达，缺少合法迁移约束 | 为 run/step 建立显式状态迁移表、乐观锁版本号和审计事件。 |
| 配置 | 模型、向量库、超时和重试分散，局部有硬编码 | 所有运行参数配置化并启动校验；敏感配置从 Vault/KMS/Nacos 加密配置读取。 |
| 向量数据库 | embedding 模型不可用，导入参数被硬编码 | 先恢复真实模型契约，再增加批处理、限流、断点续传、质量评估和索引版本切换。 |
| 错误处理 | 异常主要直接透传给 SSE/调用方 | 统一错误码、用户可读错误、可关联 requestId/runId 的安全日志，避免泄露上游详情。 |
| 数据治理 | 日志与模型输入可能包含业务数据 | 定义数据分级、脱敏、留存/删除周期、加密与访问审计策略。 |

## 6. 建议的下一步路线

### 阶段 A：让最小闭环可靠可验收（P0）

1. 修复向量导入：移除硬编码参数；接入确实可用的 embedding 服务/模型；建立一个 1356 维端到端导入与检索验收用例。
2. 建立正式认证与租户上下文：替换临时认证；从 token 获取用户、租户和权限；关闭或保护调试接口。
3. 为 run/step 状态机补充单元测试：幂等、合法状态迁移、超时、重试、取消、租约过期和恢复。
4. 对 `/api/ai/chat` 定义版本化 SSE 事件协议，并完成前端最小客户端：SSE 解析、runId 保存、取消和错误展示。
5. 对学生查询和知识检索增加字段/数据权限及结果脱敏，形成一条安全的只读工具链路。

### 阶段 B：形成可运营的 RAG 与工具平台（P1）

1. 实现文档上传、解析、切分、索引任务、失败重放和知识库运营 UI。
2. 接入任务队列/worker，支持跨实例执行和从 PLAN/TOOL/COMPOSE 的完整恢复。
3. 增加模型调用限流、超时、有限重试、熔断和成本预算；所有指标按 tenant/model/tool 聚合。
4. 建立工具定义审批、版本与灰度机制，并在部署时校验数据库定义与 Java 执行器匹配。
5. 引入 OpenTelemetry/Micrometer、Prometheus/Grafana 和集中式日志；核心事件关联 requestId、runId、stepId。

### 阶段 C：企业级规模化与质量治理（P2）

1. 建立离线评测集：意图识别、工具选择、参数准确率、RAG 命中率、引用正确率、拒答率与成本。
2. 建立 CI 门禁：单元测试、集成测试、模型 mock、数据库迁移校验、前端类型检查和安全扫描。
3. 为写操作引入显式确认、审批、人机协作和不可抵赖审计；默认只读。
4. 建立多租户配额、数据隔离、密钥轮换、备份恢复和灾难演练能力。

## 7. 近期验收标准

- 给定一个 `idempotencyKey` 重复提交聊天请求，只产生一个有效 run，不重复执行工具。
- 任一工具超时后按策略重试；取消请求能够阻止后续步骤，恢复调度能够领取到期工具步骤。
- 使用指定知识库和文档版本调用导入接口，只导入该范围的分块，所有向量均为 1356 维且可检索。
- SSE 客户端能显示 `runId`、规划、工具执行、token、完成和失败状态，并能发起取消。
- 未授权用户无法访问学生敏感字段、其他租户会话、知识库或 run/step 记录。
- CI 在无真实模型密钥的环境使用 mock 完成后端测试、前端类型检查和数据库迁移校验。
