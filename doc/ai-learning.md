## 1. 项目目标

SMS 的目标是建设面向企业业务的 AI 平台，而非单次聊天接口。完整目标能力包括：

```text
身份、租户与权限
  -> 会话与上下文
  -> 模型路由、配额与成本控制
  -> 任务规划与受控工具调用
  -> 企业知识库与可追溯 RAG
  -> 流式交互、运营管理和人工干预
  -> 审计、评测、监控、告警与持续交付
```

当前项目已从核心工程原型进入产品与运营闭环阶段。系统管理、可恢复聊天、知识入库运营及 AI 任务查询均已实现前后端代码，并通过定向数据库测试和前端构建；真实模型/向量联调、生产可靠性和交付治理仍需完成。

## 3. 已完成功能

### 3.1 AI 会话与任务编排

- `ConversationApplicationService` 已实现 `PLAN -> TOOL -> COMPOSE` 会话编排。
- 支持 `idempotencyKey`；重复请求复用 `AiTaskRun`，只有成功 claim 的请求启动工作流并记录请求日志。
- 已持久化 `ai_task_run`、`ai_task_step`、AI 请求日志和工具执行日志。
- 已新增 `ai_chat_conversation`、`ai_chat_message` 及公共实体、Mapper 和历史服务；工作流执行时记录用户问题，回答完成回调记录完整助手消息。
- 聊天历史按租户与用户隔离，记录首次认证会话；消息关联 `conversationId`、`runId` 和序号。行锁、事务、排序、去重和跨登录恢复已通过真实 MySQL 测试。
- 已提供本人对话列表、消息分页及 run 快照，前端支持历史恢复、未完成任务重接及失败重新生成；Redis 记忆可从持久化历史初始化。
- 聊天先提交任务取得 runId，再通过 SSE 接收 Redis Stream；保留事件并使用事件 ID 续读，流过期后从持久化完整回答恢复终态。
- run 完成、失败与取消使用原子字段更新，取消后忽略晚到 token/成功回调；LangChain4j 流句柄可主动取消，跨实例通过数据库取消标记协作。
- 支持工具步骤超时、指数退避重试、租约超时回收和取消标记。
- SSE 支持 `start`、`planning`、`executing`、`generating`、`token`、`done`、`error` 事件。
- SSE 增加游标、心跳和完整 `snapshot`，中文/emoji 使用 UTF-8 输出；前端有限次数自动重连，手动恢复复用同一幂等键，重新生成使用新键。
- 工作流线程池、步骤超时、最大尝试次数、缓存 TTL、SSE 超时和聊天记忆窗口均配置化。

### 3.2 模型、工具与业务集成

- 模型定义可从数据库加载，支持别名、启用状态、回退别名和 OpenAI/DeepSeek 兼容适配。
- API Key 支持从 Spring `Environment` 读取，并回退到操作系统环境变量。
- 已有学生查询与知识检索两个领域工具方向。
- `AiToolRegistry` 校验工具定义与 Java 执行器的领域一致性，并记录工具调用结果。

### 3.3 知识库与向量数据

- 已有知识库、文档、版本、分块明细和入库任务的 MySQL 数据结构。
- 已实现 MySQL 分块读取、OpenAI 兼容 embedding 请求、PostgreSQL/pgvector upsert，以及 pgvector/Milvus 检索适配。
- 知识库、文档元数据、版本、分块及入库任务均有管理接口和前端页面，文档采用软删除并保护活跃入库任务。
- 支持最大 4MB 的 UTF-8 TXT/MD/CSV/JSON/HTML、DOCX 和文字型 PDF；解析限制正文长度、PDF 页数、DOCX 解压大小和外部实体。
- 切分采用 Unicode codepoint，支持 FIXED/PARAGRAPH、100–8000 字符及受限重叠；每个文档版本保存内容摘要、原件位置、切分策略快照和 staging 分块。
- 入库接口按知识库/文档版本创建持久化任务并立即返回 QUEUED 和 jobIds；默认选择每文档当前版本，每次最多 200 个版本，embedding 分批异步执行。
- 队列通过 SKIP LOCKED、120 秒租约和 UUID worker token 领取任务，保存已处理分块和进度，支持取消、失败重试及超时续执行。
- 向量先写 STAGING，完整成功后激活；旧版本晚完成不会覆盖新索引，成功任务可手动切换/回退。检索先按实时知识库/文档状态和生效 revision 过滤，再获取 topK。
- MySQL 元数据和 pgvector 激活不属于同一分布式事务；故障恢复步骤、配置与使用边界见 `doc/product-operations.md`。
- RAG 工具结果具备文档、分块、得分和元数据等来源追溯字段。

### 3.4 安全与系统权限

- `sms-web` 已接入 Spring Security 和 JWT；BCrypt 校验、MyBatis-Plus 持久化与权限查询由 System Provider 承担，Web 不直接访问数据库。
- JWT 签发与校验已下沉至 `sms-common-core`，使用 Auth0 `java-jwt`，可统一传递用户、会话、租户、角色、权限与数据范围声明。
- 已实现登录、刷新令牌、JWT 过滤、无状态会话校验和用户状态校验；刷新令牌轮换时会重新加载角色和按钮权限。
- 已实现用户角色和按钮权限查询；角色授权点使用 `ROLE_<roleCode>`，按钮授权点使用 `auth_remark`。
- 已增加 `sys_user`、`sys_role`、`sys_menu`、`sys_button`、关联表及 `sys_user_session` 实体与 DDL。
- `data_init.sql` 包含 77 个菜单和 50 个按钮权限（保留旧授权标识），并向 `R_SUPER` 全量授权；新菜单/按钮创建时也自动授予超级管理员。
- 用户/角色/菜单/按钮支持字段白名单 CRUD、BCrypt 密码及关联授权；菜单防循环，删除校验依赖，保护内置对象和最后一个启用超管。
- 用户和设备以 tenant 隔离；共享角色/菜单/按钮的写操作限制 R_SUPER。授权调用校验签名、真实 ACTIVE 会话与实时权限，禁止普通管理员修改其他超管或提升自身角色。
- 支持本人设备列表/下线及授权管理员的租户设备管理，响应不包含 token、JTI 或令牌摘要。
- 按钮授权标识的唯一约束已改为 `(menu_id, auth_remark)`，允许不同菜单复用 `add/edit/delete`；菜单按钮查询一次返回名称和标识，避免分别查询导致配对错位。
- 菜单 DTO 和 Web 菜单树已传递 `activePath`，保留隐藏文章详情页的菜单高亮。
- `sms-web` 是 AI 的唯一外部 HTTP 入口，在本地校验 JWT 后通过 System 校验 Redis/MySQL 会话与吊销状态，再将可信用户和会话标识经 Dubbo 传给 AI Provider。
- AI Provider 不再暴露业务 REST 或独立 JWT 过滤链；聊天、取消和知识入库均使用 `sms-ai-api` 契约。
- AI 任务查询、取消与幂等键复用校验租户和用户；同一用户重新登录可恢复旧 run，其他用户不能接收其 SSE 或历史。
- 前端登录与用户信息接口保留原契约，开发代理已转发到 `sms-web:9090`。
- 聊天流式 fetch 使用 Bearer，与普通 REST 共用令牌刷新 Promise，避免并发轮换刷新令牌；第二次 401 退出登录，刷新页面保留待完成问题、runId、游标与部分回答。
- AI 运营支持租户内 run、step、工具日志分页查询，步骤提供输入/输出详情，日志按 requestId 与 run 关联。

## 8. 阶段验收标准

- 用户可通过 `sms-ui` 登录 `sms-web`，令牌刷新、注销、按钮呈现、系统写操作、角色授权及设备下线按预期生效。
- AI 请求只能从认证上下文获取用户和会话，且无法跨用户取消或复用 run；完成租户模型和数据范围过滤后，才可验证跨租户隔离。
- 文档可上传、解析、按策略切分并提交异步入库，进度/取消/重试/索引切换可操作；真实检索返回正确的有效版本、分块、得分、来源和权限范围。
- SSE 客户端可保存 runId、展示流式状态、主动取消上游流、断线续读、刷新令牌及恢复过期流的完整回答，重试不会重复启动同一任务。
- 聊天记录按租户和用户隔离，完整问题与回答可持久化、分页查询和恢复；并发序号、重复回调及事务回滚通过真实数据库验证。
- 新旧数据库初始化/升级可重复执行且保留既有数据；所有服务同时启动时端口和注册信息符合配置，真实 Dubbo DTO 传输兼容。
- 租户运营人员只能按权限查询本租户 run/step/工具日志；本人聊天历史与 SSE 不因拥有运营权限而开放给其他用户。
- 核心路径具备回归测试、监控指标和失败告警；部署过程可重复并有数据恢复预案。
